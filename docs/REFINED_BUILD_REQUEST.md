# Refined Build Request

Create two separate, runnable controlled MVP builds for **EasyCommunity** and **ParkEasy** using the approved product goals, Easy Philosophy, Easy Platform Council decisions, role-based cross-validation model, behavioural psychology and human-factors review, patent/IP screening, evidence requirements and Project Phoenix defect-prevention lessons.

## EasyCommunity
Deliver a mobile-first installable PWA with trusted local search, verified listings, accessibility information, local notices, near-future community-impact signals, ParkEasy-supported venue discovery, saved items, and a separate administration interface for evidence-backed recommendations and decision audit. Preserve EasyCommunity as a lightweight community reference platform.

## ParkEasy
Deliver a mobile-first customer PWA, a role-specific staff operations PWA and a desktop-first Admin Control Centre. Include booking for parking, valet, wheelchair assistance and priority drop-off; CarePass verification; audited service-state updates; event-aware near-future footfall signals; and administrator recommendations with approve, reject, defer, modify and review controls. Preserve ParkEasy as an Assisted Arrival and Inclusive Mobility Platform.

## Mandatory controls
- Separate source trees, databases and release packages
- Configuration-driven demo data
- Live/stale health indicators
- Recommendations separated from primary operational records
- Left/right single-hand mode where relevant
- Evidence and audit traceability
- Council, lessons-learned and IP registers
- Automated API, syntax and live-startup validation
- Explicit production-readiness gaps and no-go gates
- No public claim that a controlled MVP is production ready
